# Environment Configuration

Shipwright automatically handles environment variables for your deployments.

## Automatic .env File Generation

When deploying with docker-compose, Shipwright will automatically create a `.env` file if one doesn't exist, using this priority:

1. **Existing `.env`** - If found, Shipwright uses it as-is
2. **`.env.example` or `.env.template`** - Copied to `.env`
3. **Config environment variables** - From `.shipwright.yml`
4. **Minimal defaults** - Auto-generated with common variables

## Configuration Methods

### Method 1: .env.example (Recommended for Open Source)

Create a `.env.example` file in your repository:

```bash
# .env.example
POSTGRES_USER=myapp
POSTGRES_PASSWORD=changeme
POSTGRES_DB=myapp_production

DJANGO_SECRET_KEY=changeme-secret-key
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=yourdomain.com
```

Shipwright will copy this to `.env` on first deployment.

### Method 2: Config-Driven (Recommended for Private Repos)

Add environment variables directly in `.shipwright.yml`:

```yaml
version: 1

project:
  name: myapp

build:
  compose_file: docker-compose.yml
  environment:
    POSTGRES_USER: myapp_user
    POSTGRES_PASSWORD: secure_password_here
    POSTGRES_DB: myapp_prod
    DJANGO_SECRET_KEY: your-secret-key-here
    DJANGO_DEBUG: "False"
    DJANGO_ALLOWED_HOSTS: myapp.com,www.myapp.com
```

**Note:** Don't commit sensitive values to git if your repo is public!

### Method 3: Manual .env File

Create `.env` in your compose directory:

```bash
# infra/.env (if compose file is in infra/)
# OR
# .env (if compose file is in root)

POSTGRES_USER=myapp
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=myapp_production
```

## File Location

The `.env` file is created in the same directory as your docker-compose file:

- `docker-compose.yml` → `.env`
- `infra/docker-compose.yml` → `infra/.env`
- `deploy/docker-compose.prod.yml` → `deploy/.env`

## Minimal Auto-Generated .env

If none of the above exist, Shipwright creates a minimal `.env`:

```bash
# Auto-generated by Shipwright - Please update with your values
# Database
POSTGRES_USER=postgres
POSTGRES_PASSWORD=changeme
POSTGRES_DB=app

# Django/Application
DJANGO_SECRET_KEY=changeme-insecure-key
DJANGO_DEBUG=False
```

**⚠️ Warning:** Auto-generated values are insecure. Update them before going to production!

## File Ownership

When Shipwright agent runs as root (systemd service), it automatically fixes file ownership to match the deployment directory owner. Files will be owned by the directory owner, not root.

## Best Practices

1. **Use .env.example for open source projects**
   - Commit `.env.example` to git
   - Add `.env` to `.gitignore`
   - Document required variables

2. **Use config environment for private repos**
   - Keep sensitive values in `.shipwright.yml`
   - Use environment-specific configs (.shipwright.prod.yml)

3. **Never commit secrets**
   - Add `.env` to `.gitignore`
   - Use secret management tools for production
   - Rotate credentials regularly

4. **Validate on deployment**
   - Check logs for "Auto-generated .env" warnings
   - Verify environment variables are set correctly
   - Test application after first deployment

## Troubleshooting

### "env file not found" error
Shipwright now auto-creates .env files. If you see this error, you're on an old version. Update:
```bash
cd ~/shipwright
git pull
cargo build --release --package shipwright-agent
sudo cp target/release/shipwright-agent /usr/local/bin/
sudo systemctl restart shipwright-agent
```

### "Permission denied" errors
Shipwright now automatically fixes file ownership. Update to the latest version (see above).

### Variables not being used
Ensure your docker-compose file loads the .env file:
```yaml
services:
  app:
    env_file: [.env]  # ← Add this
    environment:
      - DATABASE_URL=postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
```

## Example Full Configuration

```yaml
# .shipwright.yml
version: 1

project:
  name: myapp
  framework: django

build:
  compose_file: infra/docker-compose.deploy.yml

  # Environment variables (created as infra/.env if not exists)
  environment:
    # Database
    POSTGRES_USER: myapp
    POSTGRES_PASSWORD: ${SECRET_PASSWORD}  # Can reference external secrets
    POSTGRES_DB: myapp_production

    # Application
    DJANGO_SECRET_KEY: ${DJANGO_SECRET}
    DJANGO_DEBUG: "False"
    DJANGO_ALLOWED_HOSTS: myapp.com,api.myapp.com

    # External Services
    REDIS_URL: redis://shared-redis:6379/0
    CELERY_BROKER_URL: redis://shared-redis:6379/1

deploy:
  type: docker-compose
  vps:
    host: your-server.com
    user: deploy

infrastructure:
  strategy: compose
  deploy_dir: /home/deploy/apps/myapp
  auto_detect: true
```

This configuration:
- Creates `infra/.env` with all environment variables
- Fixes file ownership to `deploy:deploy`
- Works on first deployment without manual setup
- Supports both shared and project-specific resources
